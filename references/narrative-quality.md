# 叙事与丰富度检查

用于选段、画面脚本、静帧审阅与最终人工 QA。目标是让画面有足够的信息和变化，同时易于理解；不按物件或动画数量机械打分。

## 先判断语义，再安排秒数

- 把选定原句拆为需要看懂的关系，例如问题、处理、分阶段、目标、范围。每项应对应可见状态或动作；由相邻口播承担的部分注明即可，不必全塞进一镜。
- 区分“一个核心意思”和“只有一个变化”。同一镜可以呈现输入 → 处理 → 结果，也可呈现混乱 → 分类 → 明确目标。
- 缩短选段会减少主题数量，但不必降低单镜的可读信息。比较两版时，先看语义相近的单镜，再看整段切镜、色彩和时长差异。
- 时长由口播和必要动作共同决定。8 秒镜头可先尝试 3–4 个有意义的节拍再留出读图时间，这只是起点；简单内容可更短，复杂内容可拆镜。不要把一个简单入场或裁切拉长以填满时长。

## 从原版借用完整关系

直接使用 [原版 GIF](original-examples.md) 作为 reference。记录借用的是哪些构图、物件组合、配色与动作结构；保持适合语义的设计，不必回避复用。参考选择应在脚本阶段完成，而不是生成素材后补上。

- 青绿片：地图与定位对象 → 黄色连接路线 → 下方胶片 → 剪刀。可借其上中下构图和连接关系，避免只摘出地图、剪刀而丢失中间过程与结果。
- 紫色片：大量输入 → 加工装置与协作对象 → 有组织的输出。适合筛选、整理、转化；无需为了沿用结构强加人物。
- 红色片：对象位置、作用区域、操作者形成关系。适合规划、边界、顺序；边框要表达实际作用范围。
- 黄色片：一次偏差在重复输出中放大。适合问题与后果；重复必须传达数量或因果，而非装饰。

## 静帧与动作共同设计

- 有明确主次、尺度差异、重叠层次和视觉连接。留白服务主体和字幕，不以填满画布为目标。
- 多种物件应各自承担角色。例如地图代表范围，任务卡代表阶段，目标标记代表结果，分拣或剪裁动作代表处理。不要用多个近义图标重复同一信息。
- 对需要前后对比的镜头，制作时内部检查起始问题态、关键处理态和完成态；用户审阅默认只展示完成态结果图，过程在四列表格的“预期画面呈现”中简述，不增加中间静帧确认环节。范围收窄不必让全部画面一起缩水，可把选出的内容组织成更清楚的任务卡或输出区。
- 动作要改变关系：被剪部分分离、资料进入对应容器、连接抵达目标、输出形成顺序。工具沿路径漂移而对象毫无反应，只能算移动，不能算完成处理。
- 代码基本图形适合路线、边界和标记；主体仍保留有分量的半调纸片素材。需要复杂动作时扩展本地实现，不能默默降低已确认的视觉目标。

## 人工验收记录

在项目 `qa-review.md` 简要回答：

1. 原句的关键关系分别由哪个物件、状态或动作表达？是否遗漏了“每个阶段”等重要限定？
2. 每个主要节拍让观众多理解了什么？是否存在长时间移动但没有信息变化？
3. 操作是否产生可见结果？末帧是否保留清楚、有层次的结果，而非越来越空？
4. 与选用的原版参考、相近语义的已通过镜头相比，借用了什么、哪里仍显单薄？

不要求每次都复杂。简单镜头只要符合语义、节奏和用途即可；出现不足时先调整叙事或构图，再考虑新增素材。内容修改按主流程确认，不能在既有批准记录里偷偷替换方案。
